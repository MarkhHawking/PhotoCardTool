# PhotoCard Tool

Skyrim（SSE）假发展示卡片 / 盒子世界模型生成器。把发型 NIF 渲染成木框卡片（DDS），
再一键打包成「盒子 + ESP」，或把 BSA / BodySlide 素材一起定位出来。

- 图形界面：`photocard_gui.py`（三个页签：卡片生成 / 供图拼卡 / 盒子 + ESP）
- 结构说明：`ARCHITECTURE.md`
- 第三方二进制：`materials/`（Texconv.exe、02.png、1_go.nif、盒子贴图）——运行所需，体积小，直接入库

```bash
pip install pillow numpy
python photocard_gui.py
```

打包成单文件 exe 的命令见 `ARCHITECTURE.md`。

PhotoCard Tool —— 使用说明（v19）

本版（v19）改了什么
-------------------
1. 缺贴图时不再生成半成品
   - 「⑤ 生成」改成两遍式：先生成计划并做完整预检（NIF 引用的每张贴图、盒子的 box.dds /
     box_n.dds / glass_n.dds、XML、卡片 dds），任何一项缺失就直接报错并列出清单，
     这时一个文件都不会写，Meshes / Textures 目录根本不会建出来。
   - 在 BSA 里找到的贴图不算缺失（保留原路径，不复制）。

2. 菜单栏新增「设置」
   - 路径设置…：MO2 mods 根目录 / 游戏 Data 目录 / 缓存目录，每行都有「浏览…」和「自动搜索」。
     保存后写到软件目录的 settings.json，下次启动自动读取。
   - 自动搜索 mods 根目录：常见 MO2 位置 + 读 ModOrganizer.ini 里的 mod_directory。
   - 自动搜索游戏根目录：注册表 Bethesda 的 Installed Path → Steam 的 libraryfolders.vdf → 常见库路径。
   - 扫描 BSA（mods + 游戏）：手动跑一次，把 mods 下每个 mod 的 BSA 和游戏 Data 里的 BSA
     文件名全部读出来，存进缓存（bsa_index.json.gz，默认放软件目录，17.3 万个名字约 0.9 MB）。
     扫描很快：游戏本体 23 个 BSA 0.2 秒，整个 mods 目录 0.03 秒。
   - 打开缓存目录 / 清空 BSA 缓存。
   - 缓存目录还用于 BC7 编码的临时文件（_bc7_tmp）。

本版（v18）改了什么
-------------------
1. 贴图在 BSA 里不再算“缺失”
   素材表的贴图查找顺序变成：mod 目录里的散装文件 -> mod 目录里的 *.bsa ->
   游戏 Data 目录里的散装文件 / *.bsa。命中 BSA 的行显示为
       类型：贴图 BSA      在 mod 中找到：在 Skyrim - Textures3.bsa 中（保留原路径，不复制）
   这种行不复制、也不改写 NIF 里的路径（贴图本来就由那个 BSA 提供），
   所以“其余都不缺”时可以直接生成，不会再被拦。

2. 新增「游戏 Data（查 BSA 用，可空）」输入框
   填 Skyrim 的 Data 目录（默认会尝试
   D:\SteamLibrary\steamapps\common\Skyrim Special Edition\Data）。
   留空就只查当前 mod 自己目录下的 *.bsa。
   —— 这也是回答“怎么判断游戏本体里有没有这张贴图”：把 Data 目录填进来，
      工具会把 Data 下所有 BSA 的文件名表读出来（只读名字，不解包、秒级完成），
      命中就说明本体（或任何装在那里的 BSA）里有它。

3. 「指定文件」后，“NIF 内引用”列显示相对路径
   以前只显示文件名，现在按 MO2 根目录压缩：
       <mod 目录内>      -> Textures\YunDao_Hdt\Hair\Sky074_n.dds
       <mods 根目录内>    -> 某个 Mod\Textures\x.dds
       其它位置          -> 原样绝对路径
   和 NIF 里其它路径的写法保持一致，方便核对。

技术说明（为什么只读名字就够）：
   BSA 头部记录了文件夹/文件数量与名字块长度，名字表可以直接枚举；
   工具只判断“有没有这个文件名”，不需要解压，也不会去读那几十 GB 的贴图数据。
   实测本机 Skyrim SE 的 23 个 BSA 共 17.3 万个文件，首次建索引约 0.3 秒，之后有缓存。

本版（v17）改了什么（历史）
-------------------
1. 「改路径」换成「指定文件」（右键素材表）
   上一版让你直接编辑 NIF 里那个相对路径字符串，实际很难改对（路径存在哪儿、大小写、
   相对谁，全是坑），现在改成：右键一行贴图 -> 「指定这张贴图用的 DDS 文件…」 ->
   用文件对话框挑一个真实的 dds。行为是：
     复制这个文件到 服装 Textures 子目录（带前缀）  ->  把输出 NIF 里该槽改写成
     textures\<服装Textures子目录>\<前缀+文件名>.dds
   也就是说「源 NIF 链接的 dds 路径要改到新输出里」这一步由工具替你写好，
   你只需要告诉它“哪个槽用哪个文件”。行首会标「贴图 ✎」，改动写进日志。

2. 缺贴图不再“假装成功”，必须先处理
   只要有一张贴图既没找到、也没被你「指定文件」或「清空」，生成会直接中断，提示：
       下面 N 张贴图没找到，先在素材表里右键「指定这张贴图用的 DDS 文件」或「清空」再生成：
         Textures\YunDao_Hdt\Hair\pbw_10_hel_0007_n.dds
   （上一版是“警告并跳过”，结果 NIF 里留着坏路径，进游戏才发现缺图。）

3. 修好了提示行压在素材表上的问题
   「双击=打开文件；右键=指定…」这行提示原来和表格挤在同一个网格行，盖在白色表格区上，
   现在挪到表格下方单独一行。

保留的操作：
   清空这一行（不使用这张贴图）  —— 输出 NIF 该槽置空，不复制文件
   撤销这一行的修改            —— 回到 NIF 原始内容

本版（v16）改了什么（历史）
-------------------
1. 素材表可以改路径、可以删掉某张贴图（③ 区）
   右键素材表任意「贴图」行：
     修改这张贴图的路径…   —— 弹框里填 NIF 里应该写的相对路径（例如
                              Textures\YunDao_Hdt\Hair\Sky074_n.dds），改完立即重新定位，
                              生成时就按新路径复制，并把这个路径写进输出 NIF 的贴图槽
     不使用这张贴图        —— 把这个槽清空（输出 NIF 里该槽为空字符串，也不复制文件）
     撤销这一行的修改      —— 回到 NIF 里原本写的路径
   行首会标出来：贴图 ✎ = 已修正，贴图 ⊘ = 已移除（灰字）。
   改过的行数会写进日志；关闭程序后不保留，重新定位一次就是 NIF 原始内容。

2. 贴图缺失不再中断生成
   以前只要有一张贴图找不到就整单失败。现在会在日志里写
       「警告：mod 里找不到贴图，已跳过（NIF 保留原路径，进游戏会缺这张）：…」
   然后继续把能复制的都复制、NIF/XML/盒子/ESP 照常生成 —— 路径写错的可以先用 ③ 改对再重跑。

3. 界面重新排了一版（③ 页签）
   · 四大分区加了分隔线 + 加粗标题：① 源 ESP/② 源发型、③ mod 与素材定位、④ 命名、⑤ 输出与生成
   · ④ 命名拆成左右两个带标题的框：左边「服装（头发）」，右边「世界模型（盒子）」，
     标签右对齐、输入框等宽，不再一行塞四个控件
   · 图例移到「生成」按钮上方（原来是夹在命名和输出中间，滚下去就看不见了）
   · 素材表从 7 行加高到 9 行，表下加了一行操作提示（双击/右键能干什么）
   · 生成按钮去掉多余的「⑤」编号（分区标题已经有了）

1. 卡片预览：直接用系统默认程序打开
   「卡片:」旁边的「预览」不再先转 PNG，直接调用系统默认程序打开选中的 dds
   （和素材表里双击打开文件的行为一致）。想用哪个看图软件看 dds，在系统里设好关联即可。

2. 修好了被写坏的贴图路径（含换行/制表符）
   有些 mod 的 NIF 贴图槽里混进了控制字符，例如 Yundao 的 skyblonde.nif：
       Textures\YunDao_Hdt\Hair\sky074<换行>textures\_n.dds
   这本来应该是 ...\sky074_n.dds。以前它会原样显示成两行、并报「✗ 缺失」（因为文件确实不存在）。
   现在定位素材 / 生成时都会自动修正成
       Textures\YunDao_Hdt\Hair\sky074_n.dds
   并在日志里写「贴图路径含换行/控制字符，已修正为：…」，输出 NIF 里的贴图槽也会被改写成正确的新路径。
   实测该发型已能正常复制 new_sky074.dds / new_sky074_n.dds，不再报缺失。

3. 素材表去重
   同一张贴图被多个形状引用（例如上下两片头发各有一套贴图槽）时，只列一次，不再重复四行。

PhotoCard Tool v15 — 使用说明
================================

本版（v14）改了什么
-------------------
1. 状态提示不再挡住输入框内容
   以前是把「必填 / 请换卡片 / 随发型更新」的小色块贴在输入框右端，会盖住框尾的字。
   现在改成**框底色 + 页面图例**：
     白色 = 正常
     淡蓝 = 随发型更新（换了源发型后自动跟着改的项）
     淡橙 = 要改（生成用过的 EDID/显示名、被复用的 ESP 名、没有 XML 时的 XML 名）
     淡红 = 必填（这次生成缺它，按钮下面还会列一行「还差：…」）
   图例就印在 ④ 命名区下面一行，一眼能对上颜色。

2. 卡片可以预览了
   ⑤ 下面「卡片:」右侧多了「预览」按钮：选好 dds 后点一下，会先把 DDS 转成 PNG
   （用包内的 Texconv，输出到 dds 同目录的 _photocard_preview 文件夹）再用系统看图打开。
   非 dds 的图片直接打开。

3. 换源发型后会自动复检 ESP 文件名
   选中源发型后立刻重新检查「输出文件夹 + ESP 文件名」是否已经存在：
   存在 -> 提示变橙并写「已存在同名 ESP：将追加」；不存在 -> 绿色「新建」。
   这样换发型/换输出目录后不用再点一次生成才发现名字撞了。

4. XML 名跟着贴图一起联动，没有 XML 就清空
   定位素材时如果 NIF 引用了 XML，自动填名字并标淡蓝；
   如果这个 NIF 根本没有 XML → 输入框**清空**、标淡橙，日志写
   「该 NIF 没有 XML：XML 名已清空，生成时不复制 XML」，输出里也不会凭空多一个 physics.xml。

5. 页面可以滚动了（顺带修掉的小屏问题）
   ②③ 两页放进滚动容器：窗口矮 / 系统缩放 125% 时也能看到底部的生成按钮，滚轮可用。

 PhotoCard Tool v13  （卡片生成 / 供图拼卡 / 盒子世界模型）
====================================================
双击 PhotoCardTool.exe（无参数=图形界面）。素材在程序同级 materials\ 目录。
页签顺序：① 卡片生成 → ② 供图拼卡 → ③ 盒子 + ESP

【页签 ① 卡片生成】
  操作顺序：① 选 NIF → ② 确认输出目录/名字 → ③ 选预设或展开高级参数（预览实时更新）→ ④ 生成卡片
  - 预设一键切换：
      默认  —— 环境光 .50 / 漫反射 .55 / 边缘光 .18 / 高光 .24 / 锐度 24 / 发丝 1.8 / 伽马 1.8 / 深度关
      细节  —— 发丝厚度 1.4、高光 0.35、高光锐度 32、深度遮挡开
      柔和  —— 发丝厚度 2.0、漫反射 0.6、高光锐度 12、深度遮挡关
    点完按钮，右侧显示「当前：细节」这样的当前预设。
  - 「高级参数▸」是折叠区（默认收起），里面 9 个渲染滑条 + 深度遮挡 + 亮度自适应 两个开关。
    点一下展开（变成「高级参数▾」），再点收起；手动动任何一项，预设会显示「当前：自定义」。
  - 所有滑块都带数值框：可直接输入数字，回车/失焦生效
  - 预览 = 完整卡片（木框 + 左正面 + 右侧面），后台线程渲染（900px 内部再缩小，保证清晰）
  - 每完成一次预览，下方日志会写一行：
      预览完成 14:45:52 · Sleeperblonde.nif · 正面 0°/0°  侧面 65°/0° · 占比 92% 横向 100% ·
      发丝 1.80 伽马 1.80 深度关 · 预设 默认
    改参数/换角度/换 NIF 都会在预览完成后留下这一行，方便确认“刚才那一下到底用了什么参数”。
    日志只保留最近 400 行。预览失败也会写一行原因。
  - 正面/侧面各自有独立「旋转° / 俯仰°」；默认侧面 65°
  - 画面占比%、横向% 的改动也会即时反映在预览里（约 0.32 秒防抖）
  - 输出：<名字>.dds（BC7/DX10）、<名字>_front.png、<名字>_side.png、photo_card.png
  - 「输出路径跟随输入文件」勾选：选 NIF 自动改输出目录+输出名；取消=锁定

【页签 ② 供图拼卡】（不想渲染、或模型被拆成多个 NIF 时，用截图手工拼）
  操作顺序：① 正面点「截图」拖框 → ② 侧面同理 → ③ 确认输出名/文件夹 → ④ 生成卡片
  - 「截图」流程：
      点按钮 → 右上角倒数 2.6 秒（这期间切到要截的画面；按 Esc 或点提示条取消）
      → 全屏半透明遮罩（显示的是冻结画面，比遮罩更亮，选到哪就是哪）
      → 拖一个框：框内即所选区域，黄色边框 + 实时尺寸
      → 松开鼠标：自动取正方形（按较长边，贴屏幕边自动内收）并直接填入槽位
    多显示器 / 系统缩放下也能对准（按截屏像素换算）。
  - 「选图…」可直接用现成图片（非正方形的会自动居中裁成正方形；超过 1600px 先缩小）；
    「清空」清掉该槽位
  - 右侧实时预览整卡：和页签①「卡片生成」完全同一版式——02.png 木框 + 只占中间的
    深灰卡片区（左正面 / 右侧面），不是整块铺满
  - 尺寸：默认 1024×1024（可选 2048）；画面占比/横向% 用页签① 的默认值（92 / 100）
  - 输出：
      <名字>.dds             BC7（DX10、单 mip），尺寸同上，默认 1024×1024
      <名字>_front.png       与上面同尺寸的方图
      <名字>_side.png        与上面同尺寸的方图
      photo_card.png         整卡预览图（与页签① 同名文件，后生成者覆盖）
    生成完会自动把这个 dds 填进页签③的「卡片 dds」，接着做盒子即可。

【页签 ③ 盒子 + ESP】
  操作顺序：① 选源 ESP → ② 选发型（下拉框可打字模糊搜索）→ ③ 选 mod →
           ④ 自定义命名 → ⑤ 生成
  - ① 源 ESP：浏览选择（提供 ARMO/ARMA 模板）。选完（或回车、或点别处）立即载入：
      · 「源发型」列表自动填好（EDID — 显示名），条数写在日志里
      · 「mod 列表」自动切到这个 ESP 所在的那个 mod 文件夹
      · 自动执行一次「定位素材」，表格里直接列出该发型的 NIF / 贴图 / XML
    之后再换源 ESP，发型列表、mod 选中项、定位结果都跟着换。
  - ② 源发型：下拉框可当搜索框用 —— 直接打字过滤，忽略大小写与空格，支持跳字匹配
      （例如 yd fl 也能匹配 “YunDaoA_flower — YD Flower”）；回车或点选一项生效。
      选中后自动跟着改：
        · 新 EDID / 显示名
        · 穿着 NIF       = 源发型文件名（如 flower.nif）
        · 盒子 NIF 名    = 源发型文件名 + _box.nif（如 flower_box.nif）
        · 服装子目录     = 源发型所在目录（如 meshes\YunDao_Hdt\Hair\flower.nif → YunDao_Hdt\Hair）
        · 已选 mod 时自动定位素材
  - ③ mod 列表：同样支持打字模糊过滤；「扫描 mods」重读 MO2 mods 根目录；
      「定位素材」手动再查一次（表格：类型 / NIF 内引用 / 在 mod 中找到，缺失标 ✗）。
      素材表格里：双击一行 = 打开该文件；右键 = 「打开文件 / 打开所在文件夹」。
  - ④ 自定义命名（生成前确认，四个目录都能自己改名）：
      服装 Meshes      —— 穿着 NIF 和 XML 的去处：Meshes\<服装 Meshes>\
      世界模型 Meshes  —— 盒子 NIF 的去处：Meshes\<世界模型 Meshes>\
      服装 Textures    —— 头发贴图的去处：Textures\<服装 Textures>\
      世界模型 Textures—— 盒子/卡片/玻璃贴图的去处：Textures\<世界模型 Textures>\
      穿着 NIF 名、XML 名、盒子 NIF 名、贴图前缀
    默认值（选完源发型自动填，之后可以随便改）：
      服装 Meshes   = <源 ESP 去后缀>\Hair\<穿着 NIF 去后缀>
                      例：YunDao_Hdt_Hair.esp + flower.nif → YunDao_Hdt_Hair\Hair\flower
                      一套发型一个文件夹，发型越加越多也不会互相盖贴图/混在一起
      服装 Textures = 与服装 Meshes 同构（贴图跟着 NIF 走，找起来最直观）
      世界模型 Meshes   = BoxWorld\hair
      世界模型 Textures = BoxWorld\hair
      穿着 NIF 名 = 源发型原文件名（如 flower.nif）
      盒子 NIF 名 = 源发型文件名去后缀 + _box.nif（如 flower_box.nif）
    「贴图前缀」= 复制 DDS 时给文件名加的前缀（留空=按原名复制）。用途：
        ① 同一个 mod 里放多套卡片时避免同名贴图互相覆盖；
        ② 让贴图名字带个标记方便自己找。
        例：前缀 t_ → sleeper.dds 复制成 t_sleeper.dds，NIF 内的贴图路径同步改写。
  - ⑤ 输出文件夹（默认=程序所在目录）+ ESP 文件：
      ESP 文件 = 新 ARMO/ARMA 记录写进哪个 esp —— 文件不存在就新建；
      已存在就在末尾追加，EDID 自动改成 <新EDID>_BOX<n>，不会覆盖已有记录。
      生成内容：
        · 复制穿着 NIF → 改写其中贴图路径与 XML 字符串 → Meshes\<服装 Meshes>\<NIF 名>
        · 复制头发 DDS（可加前缀）→ Textures\<服装 Textures>\
        · 复制 XML → Meshes\<服装 Meshes>\<XML 名>，并把 NIF 里的 XML 路径改成新路径
        · 盒子 NIF + box/box_n/glass_n/卡片 四张 dds
          → Meshes\<世界模型 Meshes>\<盒子 NIF 名> 与 Textures\<世界模型 Textures>\
        · 「卡片:」是独立一行（绝对路径），带「浏览…」按钮可直接选一个现成 dds；
          页签①/② 生成完也会自动填到这里
        · ESP：ARMO.MOD2/MOD4 = <世界模型 Meshes>\<盒子 NIF 名>
                ARMA.MOD3     = <服装 Meshes>\<穿着 NIF 名>
          注意：这两条路径不带 meshes\ 前缀（游戏自己会加 Data\Meshes\）；
          也不要写 Data\ 或盘符。旧版本曾写成 meshes\...，会让角色穿戴时找不到模型（人身上什么都不显示）。
  - 页签① / 页签② 出的卡片都是 1024×1024（或 2048×2048），版式一致，盒子按原样贴。
    如果手工塞了一张 2:1 的卡片 dds，程序会自动把模板上那块 5 顶点卡片平面的 UV
    拉满 0..1，避免贴图在盒子上被裁掉上下各约 18%。

【materials\ 目录（相对 exe，不打包进 exe）】
  Texconv.exe    BC7 编码
  02.png         卡片木框底板（页签① / ② 共用，卡片区只占中间那块）
  1_go.nif       盒子模板
  box.dds / box_n.dds / glass_n.dds   盒子各面贴图
  换素材直接替换这些文件即可。

  页签③ ⑤ 那一行「模板/贴图(相对软件目录)」里，模板 / box / box_n / glass_n 都按
  「相对 exe 所在目录」解析（默认 materials\1_go.nif 这样写就好，填绝对路径也认）；
  「卡片:」是用户自己的 dds，按绝对路径处理。

 本次更新（v10）
----------------------------------------------------
  - 新增「亮度自适应」（页签① 高级参数里，默认开）：按贴图不透明像素的平均亮度反推一个增益，
    把渲染结果拉回贴图该有的明暗。原因是渲染在 sRGB 空间做光照后又套了 1/gamma，
    暗色贴图会被整体抬亮——extra part 头发最容易发灰、发白。

    暗色头发明显回到应有的深浅（例：Sleeperraven 002_hairalpha5 亮度 0.478→0.281，
    NifSkope 参考约 0.214）。想回到旧观感就取消勾选这项，或用 --autobright 0。
